Dimension 2: AI concept coverage quality
----------------------------------------

Objective: To evaluate the ontology's capability to describe AI systems themselves and to cover both the AI security domain and the AI trustworthiness domain — this is the key dimension that distinguishes an AI security and trustworthiness ontology from a general security ontology.

Evaluation metrics
~~~~~~~~~~~~~~~~~~

1)  **AI Concept Coverage Rate** — Whether the ontology covers the core constituent elements of AI (data, model, algorithm, network architecture, layer, training strategy, etc.).

> Assessment method: Concept comparison with reference ontologies such as AIO [b-AIO].

2)  **AI Lifecycle Coverage Rate** — Whether the ontology covers concepts across all stages of the AI lifecycle.

> Assessment method: Cross-reference with the AI lifecycle defined in standards such as ISO/IEC 27090.

3)  **AI Type Coverage Rate** — Whether the ontology covers the main AI types (discriminative AI, generative AI, LLM, AI agent, etc.).

> Assessment method: Expert review + literature analysis.

4)  **AI Capability Dimension Coverage Rate** — Whether the ontology covers AI capability dimensions such as perception, reasoning, decision-making, planning, and autonomous action.

> Assessment method: Expert review.

5)  External AI Ontology Alignment — Degree of conceptual mappability between the ontology and external AI ontologies such as AIO and W3C ML-Schema.

> Assessment method: Ontology alignment analysis tools.

6)  **AI Ethics Concept Coverage Rate** — Whether the ontology covers ethical dimensions such as bias, fairness, explainability, and transparency.

> Assessment method: Comparison with AIO Bias branch, etc.

7)  **AI Security Domain Coverage Rate** — Whether the ontology covers the AI security domain: the core types of threats, the vulnerabilities and risks they exploit, and the controls that address them.

> Assessment method: Cross-reference with the security requirements R-AS-01 to R-AS-06 in clause 7.2, plus expert review.

8)  **AI Trustworthiness Domain Coverage Rate** — Whether the ontology covers the trustworthiness characteristics of AI systems (reliability, availability, resilience, safety, robustness, privacy, transparency, explainability, fairness and accountability) and relates each characteristic to the security concepts it depends on.

> Assessment method: Cross-reference with the trustworthiness requirements R-AT-01 to R-AT-06 in clause 7.2, plus expert review.

Evaluation methods
~~~~~~~~~~~~~~~~~~

1)  Reference ontology comparison method:

- Using AIO’s eight branches (Bias, Layer, Machine Learning Task, Mathematical Function, Model, Network, Preprocessing, Training Strategy) as a reference baseline;

- Checking whether the AI security and trustworthiness ontology covers these core AI concepts, and whether security-related extensions can be built on top of these concepts.

2)  LLM-assisted coverage analysis:

- Using an LLM to generate a complete list of core AI system concepts;

- Comparing the ontology’s existing concepts with the LLM-generated list to calculate the coverage rate.

3)  Expert review:

- Inviting AI domain experts to evaluate the accuracy and completeness of the ontology’s description of AI systems.
