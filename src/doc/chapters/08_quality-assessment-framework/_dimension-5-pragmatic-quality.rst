Dimension 5: Pragmatic quality
------------------------------

Objective: To evaluate the usability and effectiveness of the ontology in practical application scenarios. The competency questions and the evaluation tasks cover the trustworthiness characteristics and their assurance in the same way as the security concepts.

Evaluation metrics
~~~~~~~~~~~~~~~~~~

1)  **Requirement Coverage** — Whether the ontology satisfies all requirements defined in Part 1.

> Assessment method: Item-by-item requirement mapping check.

2)  **CQ Answer Quality** — Whether the ontology can correctly answer predefined competency questions.

> Assessment method: Construct SPARQL queries, verify query result quality.

3)  **Documentation Completeness** — Whether the ontology’s accompanying documentation is complete and understandable.

> Assessment method: Using existing well-described metric.

4)  **Task Completion** — Effectiveness of using the ontology to complete specific tasks (e.g., threat modelling).

> Assessment method: Case studies + user evaluation.

5)  **Operability** — Whether the ontology is easy to import, query, and integrate.

> Assessment method: Technical verification.

Evaluation methods
~~~~~~~~~~~~~~~~~~

1)  Competency Question (CQ) testing:

- Predefine 20-30 typical competency questions (e.g., “List all types of poisoning attacks against AI training data”);

- Convert CQs into SPARQL queries and verify whether the ontology returns correct results;

- Use an LLM to assist in generating CQs and evaluating answer quality.

2)  Case studies:

- Select 2-3 real-world scenarios (e.g., “Conduct security threat modelling for a generative AI service”);

- Use the ontology to complete the scenario tasks and evaluate its effectiveness and efficiency.

3)  User evaluation:

- Invite ITU-T experts to use the ontology and collect feedback;

- Evaluation metrics: ease of use, difficulty of understanding, task completion time.
